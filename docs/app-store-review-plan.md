## Item 1: Session Tokens for Authentication

**Status:** Keep as-is — no action needed.

The cookie-based JWT authentication is only used by the internal admin portal (`/portal/*` routes) in `cross-border-agent/app/utils/portal-auth.server.ts`. This portal is:
- Protected by a separate username/password login (`/portal/login`)
- Not accessible to merchants — it is an internal superadmin tool
- Completely isolated from the embedded Shopify app routes (`/app/*`)

The merchant-facing embedded app correctly uses Shopify session tokens via `@shopify/app-bridge` and `authenticate.admin()`. Shopify reviewers evaluate the merchant-facing experience; the portal is a private back-office tool and does not violate this requirement.

## Item 2: Authenticate Immediately After Install

**Status:** Manual verification only.

The root route `/` in `cross-border-agent/app/routes/_index/route.tsx` serves a public landing page when no `?shop=` parameter is present. However, this is not a problem because:

- Shopify's install flow always provides the `shop` query parameter. When a merchant clicks "Install" from the App Store, the request includes `?shop=xxx.myshopify.com`.
- The loader immediately redirects to `/app` (which calls `authenticate.admin()`) when `?shop=` is present.
- A merchant can never reach the marketing landing page through the normal Shopify install/open flow.

### Manual Verification

Confirm that clicking "Install" and "Open app" from the Shopify App Store listing always includes the `shop` parameter and lands the merchant directly in the authenticated app, never on the marketing page.

## Item 3: Redirect to App UI After Installation

**Status:** Manual verification only.

The current flow is a two-phase OAuth architecture:

```
Merchant → Shopify App Store → "Install"
  → API Backend: GET /?shop=xxx
  → Redirect to Shopify /admin/oauth/authorize
  → Merchant accepts permissions
  → API Backend: GET /api/auth/callback?code=...
  → API exchanges code for token, stores in DB
  → Redirect to UI: /auth/login?shop=xxx
  → UI: authenticate.admin() triggers App Bridge auth
  → UI: afterAuth hook syncs token to backend
  → Merchant lands in /app (embedded UI)
```

The `auth.login` route is not a dead end — it invokes `login(request)` from `shopify.server.ts` which triggers the standard Shopify App Bridge embedded authentication. The merchant sees at most a brief loading state before landing in the app.

### Manual Verification

Walk through the full install flow end-to-end. After accepting OAuth permissions, confirm the merchant lands in the embedded app UI (`/app`) without seeing a login form or getting stuck on an intermediate page. The `auth.login` page with the "Shop domain" text field should never appear during the normal install flow; it's only a fallback for direct URL access.

## Item 4: OAuth After Reinstall

**Status:** Manual verification only.

The reinstall handling is robust with multiple safety nets:

1. **Root route** (`_index/route.tsx`): Calls backend `/api/admin/reinstall-path` to determine the right destination.
2. **App shell** (`app.tsx`): Token health check probes `{ shop { name } }` GraphQL; on failure, deletes stale sessions and re-triggers OAuth.
3. **afterAuth hook** (`shopify.server.ts`): Syncs fresh token to backend immediately.
4. **Backend reinstall-path** (`oauth.py`): Marks shop active, handles grace periods, and routes to the correct destination.

The concern about backend unavailability is mitigated because:
- The root route has a try/catch that falls back to `/app` if the backend call fails.
- The app shell independently validates the token and re-triggers OAuth if it's stale.

### Manual Verification

Uninstall the app, then reinstall it. Verify:
- [ ] OAuth triggers immediately
- [ ] The merchant lands in the app UI
- [ ] If the merchant was on a paid plan with grace period, they see the grace banner
- [ ] If expired, they are sent to the pricing page

## Item 5: Initiate Installation From a Shopify-Owned Surface

**Status:** Keep as-is — no action needed.

The `auth.login.tsx` page with the "Shop domain" text field is the standard Shopify app template generated by `@shopify/shopify-app-react-router`. Every app scaffolded with Shopify CLI includes this exact pattern. It serves as a fallback route when a user navigates directly to `/auth/login` without a `shop` parameter (which does not happen in normal flows).

This is not a custom-built shop domain prompt — it is Shopify's own template code. The primary install flow is always initiated from the Shopify App Store (a Shopify-owned surface), and the `shop` parameter is always provided by Shopify.
